# Deploying SwiftDrop for free

Three free accounts, no credit card: **Neon** (Postgres) → **Render** (API) → **Vercel** (frontend).
Budget about 25 minutes end to end. Do the steps in order — each one produces a
value the next one needs.

| Piece | Host | Free tier limits |
|---|---|---|
| Postgres | [Neon](https://neon.tech) | 0.5 GB storage, no expiry |
| FastAPI API | [Render](https://render.com) | 750 instance-hours/month, sleeps after 15 min idle |
| React frontend | [Vercel](https://vercel.com) | 100 GB bandwidth/month, always on |

---

## 1. Database — Neon

1. Sign up at **neon.tech** with GitHub.
2. **Create project** → name it `swiftdrop` → pick the region closest to you.
3. On the dashboard, open **Connection string** and copy it. It looks like:

   ```
   postgresql://neondb_owner:npg_xxxx@ep-cool-bird-12345.us-east-2.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```

   Copy it **exactly as Neon gives it** — the app rewrites the driver prefix and
   strips the libpq-only parameters itself. Keep this tab open.

> You do not need to run `schema.sql` or `seed.sql` by hand. Render runs
> `python -m db.bootstrap` on every start; it creates the tables and loads the
> demo accounts the first time, then skips seeding so visitor data survives.

---

## 2. API — Render

1. Sign up at **render.com** with GitHub.
2. **New → Blueprint** → select the `Swiftdrop` repo → **Connect**.
   Render reads [`render.yaml`](render.yaml) and pre-fills everything except the secrets.
3. It will prompt for the two values marked *sync: false*:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `CORS_ORIGINS` | leave as `http://localhost:5173` for now — you'll fix it in step 4 |

   `SECRET_KEY` is generated by Render automatically. Never reuse the placeholder
   from `config.py` on a public URL.
4. **Apply**. The first build takes 3–5 minutes.
5. When it goes live you get a URL like `https://swiftdrop-api.onrender.com`.
   Check it: opening **`/health`** should return `{"status":"ok",...}` and
   **`/docs`** should render the interactive API reference.

**If the deploy fails,** open the log and read the `[bootstrap]` lines — a failure
there means `DATABASE_URL` is wrong or the Neon project is paused.

---

## 3. Frontend — Vercel

1. Sign up at **vercel.com** with GitHub.
2. **Add New → Project** → import `Swiftdrop`.
3. Set **Root Directory** to `frontend`. Vercel detects Vite on its own.
4. Under **Environment Variables** add:

   | Key | Value |
   |---|---|
   | `VITE_API_BASE_URL` | your Render URL, e.g. `https://swiftdrop-api.onrender.com` — **no trailing slash** |

5. **Deploy**. You get a URL like `https://swiftdrop.vercel.app`.

---

## 4. Point the API back at the frontend

The API rejects browser requests from origins it doesn't know, so it needs the
Vercel URL:

1. Render → your `swiftdrop-api` service → **Environment**.
2. Edit `CORS_ORIGINS` to your Vercel URL, no trailing slash:

   ```
   https://swiftdrop.vercel.app
   ```

   Several origins are fine, comma-separated:
   `https://swiftdrop.vercel.app,https://www.your-domain.com`
3. **Save changes** — Render redeploys automatically (~2 min).

Now open your Vercel URL and sign in.

## What to expect from the free tier

**The API sleeps after 15 minutes of inactivity.** The first request after that
waits roughly 50 seconds while Render restarts the container. This is normal, not
a bug. The frontend handles it: `ServerBanner` pings `/health` on load and shows
"Waking the server up" so the page never looks frozen, and the API client waits up
to 90 seconds instead of failing at 15.

Render's free tier gives **750 instance-hours per month across your whole
account** — enough for one always-awake service, or several that sleep. Pinging
this API to keep it warm 24/7 would consume the entire budget on its own.

**Neon suspends an idle database** after 5 minutes and wakes it on the next query,
adding a second or so. Free Neon projects are deleted after long total inactivity,
so open the dashboard occasionally if the project matters.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Browser console: *blocked by CORS policy* | `CORS_ORIGINS` on Render doesn't exactly match the Vercel URL. No trailing slash, and `https://` not `http://`. |
| *relation "users" does not exist* | Bootstrap didn't run. Check the Render start-up log for `[bootstrap]`. |
| *unrecognized configuration parameter "channel_binding"* | An older build without the DSN normaliser in `db/connection.py`. Redeploy from `main`. |
| Refreshing `/driver` gives a Vercel 404 | `frontend/vercel.json` is missing — it rewrites all paths to `index.html` for React Router. |
| First login times out | Cold start. Wait for the banner to clear, then retry. |
